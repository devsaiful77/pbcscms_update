সংক্ষেপে:
  এটা একটা cron/scheduler script। এটা খোলা (pending) reference/ticket
  গুলো খুঁজে বের করে, প্রতিটার জন্য Laravel app-এর
  /sendEscalationEmail URL hit করে। Laravel সেখানে হিসাব করে ticket টা
  কত working-minute ধরে পড়ে আছে, SLA পার হলে issue_breaches table-এ
  entry দেয় আর escalation email "queue" করে (outgoing email table-এ)।

 STEP 2: EscalationEmailController@sendEscalationEmail
---------------------------------------------------------------------
  a) user/passwd check (escmailusr / Pwd@!123) আর ref_ref খালি না।
  b) reference-এর start time বের করে:
       - শেষ approved comment (comments.isapproved = 1, MAX id) এর time
       - comment না থাকলে reference.date
     (form_status = 11 হলে কিছুই করে না)
  c) start time থেকে এখন পর্যন্ত "working time" হিসাব (minute-এ):
       - working_days table (status = 1) → ছুটির দিন বাদ
       - working_hours table → office_from / office_to
         (না থাকলে default 10:00:00 – 18:00:00)
       - মাঝের পুরো working day প্রতি 8 ঘণ্টা (hardcoded 8)
       - প্রথম দিন: start time → office_to (বা একই দিন হলে এখন পর্যন্ত)
       - শেষ দিন (আজ): office_from → এখন (office_to পার হলে পুরো দিন)
       queueDurationInMinutes = (মোট ঘণ্টা * 60) + মোট মিনিট
  d) issue_breach($ref, $queueDurationInMinutes) call করে
     → true হলে "Success", না হলে "Failed" return।


---------------------------------------------------------------------
 STEP 3: issue_breach()  (core.php:708)
---------------------------------------------------------------------
  reference + issue_workflows join করে issue-এর flow_type দেখে।
  একটা ticket সর্বোচ্চ 4 বার escalate হয় (issue_breaches count < 4)।

  [A] flow_type == FORWARD
      - SLA = issue_workflows.complain_sla_time
      - প্রতিটা আগের breach-এর জন্য settings.forward_time যোগ হয়
          threshold = complain_sla_time + (আগের breach সংখ্যা × forward_time)

  [B] অন্য flow (maker-checker)
      - SLA = sla_maker + sla_checker  (issue_group_workflows থেকে,
        বর্তমান subgroup-এর জন্য)
      - threshold = SLA × (আগের breach সংখ্যা + 1)
      - breach count শুধু বর্তমান subgroup ধরে গোনা হয়

  যদি working-minutes > threshold:
      issue_breaches-এ নতুন row insert
        (issue_id, reference_no, subgroup_id, group_id, department_id,
         division_id, breach_time, time, is_sent_* flag)
      তারপর কততম breach সেই অনুযায়ী email যায়:

        1ম breach → sentSubgroup()   → subgroup-এর user যাদের
                                        user_units.is_email_allow = 1
        2য় breach → sentGroup()      → group head
                                        (user_units.is_group_info_head = 1)
        3য় breach → sentDepartment() → department head
                                        (user_units.is_department_head = 1)
        4র্থ breach → sentDivision() → division head
                                        (user_units.is_division_head = 1)

      সব ক্ষেত্রে users.status = 1 এবং email খালি না হতে হবে।

 পুরো flow এক নজরে
---------------------------------------------------------------------
  Cron
   └─ Schedule-Escalation.php
        ├─ DB থেকে open ticket list (S%/C%)
        └─ প্রতিটা ticket → GET /sendEscalationEmail?ref_ref=...
              └─ EscalationEmailController
                   ├─ শেষ approved comment / ref date থেকে working-minutes
                   └─ issue_breach()
                        ├─ SLA threshold পার? না → কিছু না
                        └─ হ্যাঁ → issue_breaches insert
                                 → subgroup / group / dept / division
                                   (1ম/2য়/3য়/4র্থ breach)
                                 → OutgoingEMAIL queue (status 3)
